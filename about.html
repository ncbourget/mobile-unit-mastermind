read this first

mastermind is early. it works, it saves real files, and it is not perfect yet. here is what it can and can't do, and where your files go.

starting a new site

you don't need a folder or a repo to start. on the first screen, give the site a name and pick one:

  • start in this browser works in any browser. the site is kept in this browser's storage until you press download, which gives you a zip with one folder inside: your pages, mastermind.json, photos, fonts and the files that draw the pages. unzip it and that folder is your site. put it on any host, push it to github, or open it again later with open a folder.
  • make it in a new folder needs chrome or edge. the folder picker has a new folder button. make one, pick it, and mastermind saves straight into it from then on.
  • a site kept in this browser stays through quitting and restarting. it's gone if you clear this browser's cookies and site data, or if you only used a private window. safari also clears it if you don't open mastermind for 7 days.
  • mastermind asks the browser to keep the site even when your disk fills up. chrome and edge usually agree on their own, firefox asks you. if the browser says no, the continue button tells you.
  • the toolbar and the continue button show when you last downloaded, and turn yellow when you have changes that aren't in a download yet.
  • this browser holds one site at a time. starting another one throws the first away, so download it first.
  • double-clicking index.html in the downloaded folder shows the desktop version. the phone layout, language switching and galleries need the folder served from a host, or opened in mastermind.

browsers

  • open a folder only works in chrome and edge (and other browsers built on chrome, like brave, arc and opera). safari and firefox don't let websites open a folder on your computer.
  • connect a github repo and start in this browser work in any up to date browser.
  • mastermind is built for a laptop or desktop screen. it opens on a tablet but it's cramped, and phones are not supported.
  • if photos or fonts stop showing up after a hard reload (shift + reload), reload once more the normal way.

where your files go

nowhere but your own folder, your own repo, or this browser's own storage. there is no mastermind account and nothing is uploaded to a mastermind server.

  • folder: files are read and written straight to the folder you picked.
  • github: this browser talks to github directly with your token. make a fine-grained token that can only see the one repo, give it contents: read and write, and set it to expire.
  • remember on this computer keeps the token in this browser. don't tick it on a shared or school computer. forget the token on the connect screen clears it.
  • changes you haven't saved stay in this browser, so a closed tab can come back. they are not backed up anywhere else.

saving and overwriting

saving writes these files into your site:

  • mastermind.json, which holds every page you made in mastermind. this is how mastermind knows a site is its own and reopens it exactly, with nothing to interpret. sites saved by an older mastermind have a site.json instead. mastermind still opens those and renames the file to mastermind.json on the next save. a site.json that mastermind didn't make is left alone.
  • one index.html per page, plus 404.html
  • render.js, site.js and page.css, which draw the pages. they are replaced with the newest version on every save, which is how your site picks up mastermind updates.
  • fonts.css and a favicon, only if your site doesn't have them yet

what gets overwritten

  • the pages mastermind makes are rebuilt from mastermind.json every time you save. if you edit one of those html files by hand, the next save replaces your edit. make changes in mastermind, or keep hand-written pages separate.
  • if saving would replace a file mastermind didn't make, like your own index.html, it lists the files and asks first. say no and nothing is written. say yes and it keeps a copy of each one first (see backups below).
  • on github, if someone else pushed since you connected, mastermind stops instead of overwriting their work. reconnect to pick up their changes, then save again.
  • on most hosts (github pages, cloudflare pages, netlify) a push to the main branch goes live a minute later. saving to github is publishing.
  • keep your site in git, so any save can be rolled back.

backups

before mastermind saves over a file it didn't make, it keeps a copy next to it: index.html becomes index-backup.html, about/index.html becomes about/index-backup.html. if that name is taken, it uses index-backup-2.html and so on, so an older backup is never replaced.

  • every backup is listed in mastermind-backup.json, with what it's a copy of and when. mastermind never edits or deletes a backup.
  • a backup still works as a page. open yoursite.com/index-backup.html to see your old homepage, with its own css and scripts.
  • to go back, delete the mastermind version and rename the backup to its old name.
  • your other files, like style.css or script.js, are never touched. mastermind only writes the files listed above, plus the photos you add.

grid or freeform

every page has a layout, set in the page tab. new pages start with the same layout as the page you're on.

  • grid: things snap to columns and rows, and the phone version is built from desktop for you.
  • freeform: place anything anywhere, nothing snaps. switching a page to freeform keeps everything where it is.
  • on a freeform page, positions and sizes scale with the width of the screen, but text stays the size you set. on a much narrower or wider window, text can run into the things around it. check your page at a few window sizes before you save.
  • phones get their own layout, stacked top to bottom from the desktop page. move things in phone view to change only the phone. rebuild the phone layout from desktop starts the phone over.
  • switching a freeform page back to grid snaps everything to the nearest columns and rows, and the phone layout is rebuilt from desktop.
  • blocks shared across every page stay on the grid, and so does a background set to the whole page.

sites you coded yourself coming

mastermind will be able to read a page you wrote by hand and make an editable copy of it, one page at a time. pick the page in the page menu and press interpret. pages you don't interpret are never touched, so hand-written and mastermind pages can live in one site.

it's a best guess, not a perfect copy:

  • javascript gets flattened. mastermind reads what the page looks like once it has loaded, not what your scripts do. menus that open, sliders, toggles, things that move or react to clicks come across as still pictures of themselves, or not at all. your .js files stay in your site, but the mastermind copy of the page doesn't use them.
  • hover effects and animations are dropped.
  • mastermind has two layouts, desktop and phone. a page that changes at several screen widths gets the closest match at each end, and the widths in between are approximated.
  • forms and deeply nested layouts come out roughly right, not exact.
  • on a grid page things snap to columns and rows. on a freeform page mastermind will keep the exact positions from your code instead.

until then you can still add new mastermind pages next to your hand-written ones. mastermind will ask before it touches your files.

using it in a codespace

the open a folder button opens a folder on your own computer, not inside a codespace. in a codespace, connect with github instead:

  1. open mastermind and connect the repo your codespace is working on.
  2. design and save. mastermind pushes a commit.
  3. in the codespace terminal, pull it in:
git pull

you can also run mastermind inside the codespace itself. download it into the codespace:

git clone https://github.com/ncbourget/mobile-unit-mastermind.git
cd mobile-unit-mastermind && python3 -m http.server 8000

open port 8000 from the ports tab, then connect with github as above.

a mastermind command coming

a mum command you install once. run it inside any site's folder and mastermind opens with that folder, in any browser, with no token needed. mum update gets the newest version. nothing is added to your site's repo.

putting mastermind inside your site

for a group, you can keep mastermind at an address on your own site, like yoursite.com/mastermind/, so everyone opens the same editor.

  1. download mastermind: on its github page, code → download zip, or clone it as above.
  2. make a folder named mastermind at the top of your site and put every mastermind file in it.
  3. push your site. when it's live, open yoursite.com/mastermind/.
  4. each person connects with github using their own token, so each person needs write access to the repo.
  • mastermind won't make a page named mastermind, so it can't save over itself.
  • to update it, replace the files in that folder with a newer download and push.
  • the editor files hold no passwords or tokens. tokens stay in each person's browser. still, you probably don't want the whole internet opening your editor, so make it private:

making that page private on cloudflare

this works when your site runs on cloudflare pages, or when its domain goes through cloudflare (the orange cloud is on in dns). a plain username.github.io address can't be protected this way.

  1. in the cloudflare dashboard, open zero trust. the first time, pick a team name and the free plan.
  2. go to access → applications → add an application and choose self-hosted.
  3. set the domain to your site and the path to mastermind.
  4. add a policy: action allow, include emails, and list the people who can edit.
  5. save. anyone opening /mastermind/ now gets a sign-in code by email, and only the listed people get in.

the free plan covers up to 50 people. this hides the editor only. the rest of your site stays public, and it can't stop someone with write access to the repo. cloudflare moves its menus around now and then, so the names above may shift a little.

other limits

  • the calendar and mailing list blocks are hidden for now. they need a server to work, and mastermind doesn't run one.
  • photos are shrunk to 2400 pixels on the longest side when you add them.
  • on github, new photos wait in this browser until you save. close the tab first and they're gone.
  • very large repos (tens of thousands of files) are too big to open from the browser.
  • fonts come from your site's fonts.css. add @font-face rules there and mastermind lists them under "this site". only use fonts your license lets you put on the web.
  • screens narrower than 700 pixels get the phone layout. change it in the dev tab.
  • if your site lives in a folder of its address, like a github pages project site at username.github.io/repo-name/, set site lives at in the dev tab to /repo-name/.
  • preview needs browser storage. if your browser blocks it, preview won't open.
